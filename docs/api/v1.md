# 99staples API v1

JSON API for the Godot game client. Everything lives under `/api/v1` and is served by controllers that
inherit `Api::V1::BaseController` (`ActionController::API`): no cookie session, no CSRF token, no
redirect to `/login`.

## Health

`GET /api/v1/health`

```json
{ "status": "ok", "api_version": "v1", "min_client_version": "0.1.0" }
```

The client calls this on boot. If its own version is below `min_client_version`, it should show a
"please update" message. Bump `Api::V1::HealthController::MIN_CLIENT_VERSION` when a change breaks
older clients.

## Authentication

Every endpoint except `health` and `POST /sessions` needs a bearer token:

```
Authorization: Bearer mtg_...
```

A missing, unknown, revoked or expired token gets `401` with code `unauthorized` and a
`WWW-Authenticate: Bearer` header. When that happens, the client should drop its stored token and show
the login screen.

Tokens last 90 days, and the window slides: each use pushes `expires_at` out again, so a client
that keeps being used never has to log in again. The server stores only a SHA-256 digest of each
token. Store the raw value in the OS keychain, not in a plain settings file.

### Log in

`POST /api/v1/sessions`

```json
{ "email": "player@example.com", "password": "...", "device_name": "Manhattan desktop - MacBook" }
```

`device_name` is optional and defaults to "Game client". It labels the token on the 99staples
settings page. A successful login returns `201`:

```json
{
  "token": "mtg_...",
  "expires_at": "2027-01-02T12:00:00.000Z",
  "user": { "id": 1, "username": "player", "email": "player@example.com" }
}
```

The token appears only in this response. A wrong email or password returns `401` with code
`invalid_credentials`. Logins are throttled to 10 per 15 minutes per IP and 10 per 15 minutes per
email. Over either limit, the response is `429` with code `throttled`.

### Log out

`DELETE /api/v1/sessions` revokes the token that made the request and returns `204`. The user's
tokens on other devices keep working.

Users can also revoke tokens from the Game Sessions section of the web settings page, one at a
time or all at once, and a password reset revokes all of them. A revoked token gets `401` on its
next request.

### Current user

`GET /api/v1/me`

```json
{ "id": 1, "username": "player", "email": "player@example.com", "preferences": { "theme": "dark", "...": "..." } }
```

## Errors

Every error has the same shape:

```json
{ "error": { "code": "not_found", "message": "Couldn't find User with 'id'=-1" } }
```

| Status | `code`              | When                                       |
| ------ | ------------------- | ------------------------------------------ |
| 401    | `unauthorized`      | Missing, unknown, revoked or expired token |
| 401    | `invalid_credentials` | Wrong email or password at login         |
| 404    | `not_found`         | Unknown record, or unknown `/api/v1` path  |
| 422    | `parameter_missing` | A required parameter is absent             |
| 429    | `throttled`         | Too many login attempts                    |
| 500    | `internal_error`    | Unhandled exception (production only)      |

Branch on `code`. `message` is for logs and debugging, and its wording can change.

## Pagination

List endpoints take `page` (default 1) and `per_page` (default 25, max 100). Invalid values fall back
to the defaults. Responses put the records under `data` and the paging under `meta`:

```json
{ "data": [], "meta": { "page": 1, "per_page": 25, "total": 0 } }
```

## Serializers

Plain Ruby objects in `app/serializers/api/v1/*_serializer.rb` that respond to `#as_json`. No jbuilder,
because deck payloads are large.

## CORS

None. The native Godot client doesn't need CORS. If we ever ship a web export, add `rack-cors` scoped
to `/api/*` only.
