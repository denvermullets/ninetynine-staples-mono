# 99staples API v1

JSON API for the Godot game client. Everything lives under `/api/v1` and is served by controllers that
inherit `Api::V1::BaseController` (`ActionController::API`): no cookie session, no CSRF token, no
redirect to `/login`.

## Health

`GET /api/v1/health`

```json
{ "status": "ok", "api_version": "v1", "min_client_version": "0.1.0" }
```

The client calls this on boot. If its own version is below `min_client_version`, it should show a
"please update" message. Bump `Api::V1::HealthController::MIN_CLIENT_VERSION` when a change breaks
older clients.

## Errors

Every error has the same shape:

```json
{ "error": { "code": "not_found", "message": "Couldn't find User with 'id'=-1" } }
```

| Status | `code`              | When                                       |
| ------ | ------------------- | ------------------------------------------ |
| 404    | `not_found`         | Unknown record, or unknown `/api/v1` path  |
| 422    | `parameter_missing` | A required parameter is absent             |
| 500    | `internal_error`    | Unhandled exception (production only)      |

Branch on `code`. `message` is for logs and debugging, and its wording can change.

## Pagination

List endpoints take `page` (default 1) and `per_page` (default 25, max 100). Invalid values fall back
to the defaults. Responses put the records under `data` and the paging under `meta`:

```json
{ "data": [], "meta": { "page": 1, "per_page": 25, "total": 0 } }
```

## Serializers

Plain Ruby objects in `app/serializers/api/v1/*_serializer.rb` that respond to `#as_json`. No jbuilder,
because deck payloads are large.

## CORS

None. The native Godot client doesn't need CORS. If we ever ship a web export, add `rack-cors` scoped
to `/api/*` only.
