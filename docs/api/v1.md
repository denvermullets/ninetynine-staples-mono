# 99staples API v1

JSON API for the Godot game client. Everything lives under `/api/v1` and is served by controllers that
inherit `Api::V1::BaseController` (`ActionController::API`): no cookie session, no CSRF token, no
redirect to `/login`.

## Health

`GET /api/v1/health`

```json
{ "status": "ok", "api_version": "v1", "min_client_version": "0.1.0" }
```

The client calls this on boot. If its own version is below `min_client_version`, it should show a
"please update" message. Bump `Api::V1::HealthController::MIN_CLIENT_VERSION` when a change breaks
older clients.

## Authentication

Every endpoint except `health` and `POST /sessions` needs a bearer token:

```
Authorization: Bearer mtg_...
```

A missing, unknown, revoked or expired token gets `401` with code `unauthorized` and a
`WWW-Authenticate: Bearer` header. When that happens, the client should drop its stored token and show
the login screen.

Tokens last 90 days, and the window slides: each use pushes `expires_at` out again, so a client
that keeps being used never has to log in again. The server stores only a SHA-256 digest of each
token. Store the raw value in the OS keychain, not in a plain settings file.

### Log in

`POST /api/v1/sessions`

```json
{ "email": "player@example.com", "password": "...", "device_name": "Manhattan desktop - MacBook" }
```

`device_name` is optional and defaults to "Game client". It labels the token on the 99staples
settings page. A successful login returns `201`:

```json
{
  "token": "mtg_...",
  "expires_at": "2027-01-02T12:00:00.000Z",
  "user": { "id": 1, "username": "player", "email": "player@example.com" }
}
```

The token appears only in this response. A wrong email or password returns `401` with code
`invalid_credentials`. Logins are throttled to 10 per 15 minutes per IP and 10 per 15 minutes per
email. Over either limit, the response is `429` with code `throttled`.

### Log out

`DELETE /api/v1/sessions` revokes the token that made the request and returns `204`. The user's
tokens on other devices keep working.

Users can also revoke tokens from the Game Sessions section of the web settings page, one at a
time or all at once, and a password reset revokes all of them. A revoked token gets `401` on its
next request.

### Current user

`GET /api/v1/me`

```json
{ "id": 1, "username": "player", "email": "player@example.com", "preferences": { "theme": "dark", "...": "..." } }
```

## Decks

### My decks

`GET /api/v1/decks`

The signed-in user's decks, public and private, with the most recently changed first. It's paginated
(see [Pagination](#pagination)). `?type=commander` returns only Commander decks, and any other `type`
value is ignored.

```json
{
  "data": [
    {
      "id": 123,
      "name": "Atraxa Superfriends",
      "collection_type": "commander_deck",
      "is_public": true,
      "bracket_level": 3,
      "card_count": 100,
      "commanders": [
        {
          "card_uuid": "...",
          "oracle_id": "...",
          "name": "Atraxa, Praetors' Voice",
          "image_art_crop": "https://cards.scryfall.io/art_crop/front/...",
          "image_normal": "https://cards.scryfall.io/normal/front/..."
        }
      ],
      "color_identity": ["W", "U", "B", "G"],
      "cover_image": "https://cards.scryfall.io/art_crop/front/...",
      "updated_at": "2026-10-04T12:00:00.000Z"
    }
  ],
  "meta": { "page": 1, "per_page": 25, "total": 1 }
}
```

| Field | Notes |
| ----- | ----- |
| `collection_type` | `deck`, `commander_deck`, or another `*_deck` type. |
| `bracket_level` | 1 to 5, or `null` when the owner hasn't set one. |
| `card_count` | Counted by the decklist rule below. It covers every board, so the client can warn when a Commander deck isn't 100 cards. |
| `commanders` | The deck's `commander` board, usually one card and two for partners. It's empty for a deck with no commander. The images can be `null`, like card images. |
| `color_identity` | The union of the commanders' identities, in WUBRG order. A deck with no commander has `[]`. |
| `cover_image` | Art crop of the deck's chosen cover card, falling back to the first commander. `null` when neither has one. |

### One deck

`GET /api/v1/decks/:id`

Any of your own decks, or another user's public deck. Another user's private deck returns `404`, the
same as a deck that doesn't exist, as does a collection that isn't a deck.

```json
{
  "deck": { "id": 123, "name": "Atraxa Superfriends", "card_count": 100, "...": "same as the list above" },
  "cards": [
    { "board": "commander", "quantity": 1, "card": { "...": "card object" } },
    { "board": "mainboard", "quantity": 1, "card": { "...": "card object" } },
    { "board": "sideboard", "quantity": 2, "card": { "...": "card object" } }
  ],
  "tokens": []
}
```

| Field | Notes |
| ----- | ----- |
| `cards` | One entry per printing and board, with the commander first and then the rest in the order they were added. Rows of the same printing on the same board are merged and their counts added up. A row with no copies is left out. |
| `cards[].board` | `commander`, `mainboard` or `sideboard`. The sideboard is included even though Commander ignores it. |
| `cards[].quantity` | Counted by the decklist rule below. The `quantity` values add up to `deck.card_count`. |
| `cards[].card` | A [card object](#card-object). A printing on two boards has the same object in both entries. |
| `tokens` | Reserved for the tokens a deck makes. It's always `[]` for now. |

`?include=rulings` adds rulings to every card (see [Rulings](#rulings)).

#### Caching

The response has an `ETag` and a `Last-Modified` header. Store the `ETag` alongside the deck and send
it back as `If-None-Match`. If nothing has changed, the response is `304 Not Modified` with no body.
The ETag changes when the deck, any of its rows or any of their cards changes, when a row is removed,
and with `include`. Prefer `If-None-Match` to `If-Modified-Since`, because
`Last-Modified` only has whole seconds.

### Decklist counting rule

The deck endpoints all count a deck the same way. The client plays the deck as the deck builder shows
it, including changes that haven't been finalized yet, so a player can try a deck before building it in
paper. Every row counts:

- An owned or needed row (needed means in the deck but not owned) counts
  `quantity + foil_quantity + proxy_quantity + proxy_foil_quantity`, because finish and proxies don't
  matter in a game.
- A staged row counts
  `staged_quantity + staged_foil_quantity + staged_proxy_quantity + staged_proxy_foil_quantity`. That
  covers planned cards (added without a source collection, which stay staged even after finalizing) and
  cards being moved in from one of your collections that haven't been finalized yet. A staged commander
  is listed.

`CollectionMagicCard::DECKLIST_QUANTITY_SQL` (or `#decklist_quantity` in Ruby) gives a row's count.

## Precon decks

Preconstructed Commander decks from mtgjson, the client's ready-made opponents. Only precons with
deck type `Commander Deck` that have a commander are served. Other precons (theme decks, Brawl decks and
so on) aren't listed, and fetching one by id returns `404`. They need a token like every other endpoint.

### List precons

`GET /api/v1/precon_decks`

Commander precons, with the newest release first. It's paginated (see [Pagination](#pagination)).
`?q=` matches part of the name, ignoring case.

```json
{
  "data": [
    {
      "id": 2534,
      "name": "Turtle Power!",
      "code": "TMC",
      "release_date": "2026-03-06",
      "card_count": 100,
      "commanders": [{ "card_uuid": "...", "oracle_id": "...", "name": "...", "image_art_crop": "...", "image_normal": "..." }],
      "color_identity": ["W", "U", "B", "R", "G"],
      "cover_image": "https://cards.scryfall.io/art_crop/front/..."
    }
  ],
  "meta": { "page": 1, "per_page": 25, "total": 176 }
}
```

`commanders`, `color_identity` and `cover_image` work as they do for [user decks](#my-decks), except
that a precon has no chosen cover card, so `cover_image` is the first commander's art crop.
`card_count` adds up the commander and main board, leaving out the sideboard and tokens. `release_date`
can be `null`.

### One precon

`GET /api/v1/precon_decks/:id`

The same shape as [one deck](#one-deck), so the client loads a precon the same way as a deck of its own:

```json
{
  "deck": { "id": 2534, "name": "Turtle Power!", "card_count": 100, "...": "same as the list above" },
  "cards": [
    { "board": "commander", "quantity": 1, "card": { "...": "card object" } },
    { "board": "mainboard", "quantity": 1, "card": { "...": "card object" } }
  ],
  "tokens": [{ "...": "card object" }]
}
```

| Field | Notes |
| ----- | ----- |
| `cards[].board` | `commander` or `mainboard` (mtgjson's `mainBoard`, lowercased to match user decks). Commander first, then in mtgjson's order. The sideboard is left out because Commander doesn't use it. |
| `cards[].quantity` | The copies mtgjson lists. The `quantity` values add up to `deck.card_count`. |
| `tokens` | [Card objects](#card-object) for the tokens the precon comes with, which are the token definitions the engine can create for this deck. Each printing appears once, so a deck that ships several arts of one token lists each of them. `[]` when it has none. |

`?include=rulings` and the `ETag` / `Last-Modified` [caching](#caching) work the same as for one deck.
A precon id that doesn't exist returns `404`.

## Errors

Every error has the same shape:

```json
{ "error": { "code": "not_found", "message": "Couldn't find User with 'id'=-1" } }
```

| Status | `code`              | When                                       |
| ------ | ------------------- | ------------------------------------------ |
| 401    | `unauthorized`      | Missing, unknown, revoked or expired token |
| 401    | `invalid_credentials` | Wrong email or password at login         |
| 404    | `not_found`         | Unknown record, or unknown `/api/v1` path  |
| 422    | `parameter_missing` | A required parameter is absent             |
| 429    | `throttled`         | Too many login attempts                    |
| 500    | `internal_error`    | Unhandled exception (production only)      |

Branch on `code`. `message` is for logs and debugging, and its wording can change.

## Pagination

List endpoints take `page` (default 1) and `per_page` (default 25, max 100). Invalid values fall back
to the defaults. Responses put the records under `data` and the paging under `meta`:

```json
{ "data": [], "meta": { "page": 1, "per_page": 25, "total": 0 } }
```

## Card object

Endpoints that return cards (decks, precons, card lookup) all use this shape. The client builds its
`CardDefinition`s from it. There is one entry per printing, and each face of a multi-face card is nested
under `faces`.

```json
{
  "card_uuid": "6ab8f18f-d69a-5d89-bd06-3b37c8ebdc76",
  "oracle_id": "8dfd9baf-c3cc-4d2f-a0b0-b323b6480562",
  "name": "Prowl, Stoic Strategist // Prowl, Pursuit Vehicle",
  "layout": "transform",
  "set": { "code": "BOT", "name": "Transformers", "card_number": "1" },
  "rarity": "mythic",
  "is_token": false,
  "can_be_commander": true,
  "commander_legality": "Legal",
  "color_identity": ["W"],
  "edhrec_rank": 10287,
  "faces": [
    {
      "side": "a",
      "name": "Prowl, Stoic Strategist",
      "mana_cost": "{3}{W}",
      "mana_value": 4.0,
      "type_line": "Legendary Artifact Creature — Robot",
      "supertypes": ["Legendary"],
      "types": ["Artifact", "Creature"],
      "subtypes": ["Robot"],
      "oracle_text": "More Than Meets the Eye {2}{W} ...",
      "power": "3",
      "toughness": "3",
      "loyalty": null,
      "defense": null,
      "colors": ["W"],
      "keywords": ["Convert", "Living metal", "More Than Meets the Eye"],
      "images": {
        "small": "https://cards.scryfall.io/small/front/...",
        "normal": "https://cards.scryfall.io/normal/front/...",
        "large": "https://cards.scryfall.io/large/front/...",
        "art_crop": "https://cards.scryfall.io/art_crop/front/..."
      }
    },
    { "side": "b", "name": "Prowl, Pursuit Vehicle", "mana_cost": null, "...": "..." }
  ]
}
```

| Field | Notes |
| ----- | ----- |
| `card_uuid` | The printing (mtgjson uuid) of the front face. |
| `oracle_id` | Scryfall oracle id. It is the same for every printing of a card. |
| `name` | Full name. Multi-face cards join the face names with `//`. |
| `layout` | Scryfall/mtgjson layout: `normal`, `transform`, `modal_dfc`, `adventure`, `split`, `flip`, `meld`, `saga`, `token`, ... |
| `commander_legality` | `Legal`, `Banned`, `Restricted`, or `null` when the card has no commander legality at all (tokens, Un-cards). |
| `color_identity`, `colors` | Color letters in WUBRG order. |
| `edhrec_rank` | `null` for cards EDHREC doesn't rank. |
| `faces` | Always at least one entry, ordered by `side` (`a`, `b`, ...). A single-faced card has one face with side `a`. |
| `faces[].mana_value` | Stored once per card, so every face of a split or adventure card has the whole card's value. |
| `faces[].supertypes` / `types` / `subtypes` | In type-line order. A token's `types` include `Token`, so use `is_token` instead. |
| `faces[].power` / `toughness` | Strings, because of values like `*` and `1+*`. `null` when the face has none. |
| `faces[].loyalty` / `defense` | Starting loyalty (planeswalkers) and defense (battles). Strings, because of values like `X`. `null` when the face has none. |
| `faces[].images` | Scryfall CDN URLs. Any of them can be `null` (missing, or the art isn't out yet), so the client should show its own fallback. The two halves of a split, adventure or flip card share one image. |

How each layout maps to faces:

- Transform, modal DFC: `a` is the front and `b` is the back, each with its own image.
- Adventure: `a` is the creature and `b` is the adventure spell.
- Split, aftermath: one face per half, in printed order. Some cards have more than two halves.
- Flip: `a` is the unflipped half and `b` is the flipped half.
- Meld: a front card has two faces, its own (`a`) and the melded permanent (`b`). The melded permanent
  serialized by itself has one face, `b`.

Passing the back face of a card returns the same object as passing its front face.

### Rulings

Endpoints that return cards accept `?include=rulings`. Each card then gets a `rulings` array, oldest
first:

```json
"rulings": [{ "date": "2022-10-14", "text": "A spell cast this way enters the battlefield with its back face up." }]
```

## Serializers

Plain Ruby objects in `app/serializers/api/v1/*_serializer.rb` that respond to `#as_json`. No jbuilder,
because deck payloads are large.

Serialize a list of cards with `Api::V1::CardSerializer.many(cards, rulings: params[:include] == 'rulings')`.
It loads every card's other faces in one query and preloads all rows in one pass, so a 100-card deck
takes about 15 queries no matter how many cards it has. Use `Api::V1::CardSerializer.new(card)` only
for a single card. `MagicCard.api_preload` preloads the same associations if you need them on a
relation before serializing.

## CORS

None. The native Godot client doesn't need CORS. If we ever ship a web export, add `rack-cors` scoped
to `/api/*` only.
